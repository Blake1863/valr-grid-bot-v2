## USDT xStocks wash starvation fix

- Blake reported that some xStocks had stopped trading on the spot wash bot.
- Root cause was not a dead service. `valr-cm-spot@usdt` was healthy, but several USDT pairs had run out of base inventory and were silently cycling with `skip_bal` preflight failures.
- Live bot summaries before the fix showed zero prints for `SPYXUSDT`, `NVDAXUSDT`, `COINXUSDT`, `TRUMPUSDT`, `TSLAXUSDT`, `PUMPUSDT`, and near-dead `VALR10USDT` / `JUPUSDT`.
- Confirmed live balances on `CMSUSDT1` and `CMSUSDT2`:
  - Plenty of quote remained (`~361 USDT` combined)
  - Several bases were near zero or zero on one or both sides
- Added `bots/cm-bot-spot-py/scripts/reseed_usdt_pairs.py` to top up thin USDT-quoted base inventory with market buys on both wash subaccounts.
- Reseeded these pairs on both accounts: `SPYXUSDT`, `NVDAXUSDT`, `COINXUSDT`, `TRUMPUSDT`, `TSLAXUSDT`, `PUMPUSDT`, `VALR10USDT`, `JUPUSDT`.
- Post-reseed balances showed fresh base inventory on both accounts and reduced USDT as expected.
- Restarted `valr-cm-spot@usdt.service` to pick up logging changes.
- Confirmed post-restart prints resumed for:
  - `COINXUSDT`
  - `TRUMPUSDT`
  - `TSLAXUSDT`
  - `PUMPUSDT`
  - `VALR10USDT`
  - `JUPUSDT`
- `SPYXUSDT` and `NVDAXUSDT` had inventory restored but had not yet printed in the short verification window.
- Important code finding: `src/inventory.py` claims lazy rebalance / failure-driven replenish, but the live orchestrator never calls a rebalance path. The real self-heal for inventory starvation is still missing.
- Added summary visibility improvement:
  - `src/cycle.py` now tracks `last_print_ts`
  - `src/orchestrator.py` summary now logs `last_print=<age|never>` so dead pairs are obvious
